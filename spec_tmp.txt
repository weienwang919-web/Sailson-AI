SPD 舆情监控 AI 工具 — 数据采集与报告输出 Spec
用途：本文档拆解沐瞳 SPD 舆情监控需求 brief 中的全部数据维度，作为自研 AI 舆情工具的开发 Spec，供 Claude Code 迭代使用。源需求文档：26Y SPD舆情监控需求brief

一、任务配置层（Task Config）
每次舆情监控任务的基础配置参数。
JSON {   "task_name": "MLBB" | "SPD",   "keywords": "布尔搜索表达式（含 AND / OR / NOT）",   "platforms": ["facebook", "instagram"],   "date_range": {     "start": "2026-03-27",     "end": "2026-04-02"   },   "regions": ["global", "TH"] } 

关键说明
	•	task_name 支持多任务并行（MLBB 整体 + SPD 联动活动），一条帖子可能同时匹配多个任务
	•	keywords 直接复用客户提供的布尔表达式，工具需支持解析 AND / OR / NOT 逻辑
	•	regions 需要全球和泰国区域两个视角分别出数据
	•	区域判断逻辑：基于发帖账号归属（如 MLBB EN、MLBB TH、MLBB ID 等官方账号），UGC 内容按语言检测归类
关键词配置参考
任务
布尔表达式
MLBB
("#mlbb" OR #mlbb* OR "mlbb" OR "#mobilelegends" OR "mobilelegends" OR "MobileLegendsBangBang" ...) AND NOT ("FREEFIRE" OR "#MLB" OR "#mlbbaseball" OR "#mlbbets")
SPD
MLBB 关键词 AND (火影角色名/英雄名/皮肤名) OR 联动专属标签（如 MLBBxNARUTO、#MLBBNewSkin 等）

三、报告输出维度（Output Schema）
模块 A：社媒声量（Engagement Trends）
A1. 分日互动量趋势
JSON {   "daily_engagement": [     {       "date": "2026-03-27",       "mlbb_engagement": 125000,       "spd_engagement": 42000     }   ] } 

输出要求
	•	需要出两组趋势数据：① 全球 MLBB vs SPD ② 泰国区域 MLBB vs SPD
	•	输出为折线图数据（双线对比），需支持渲染为可视化图表
	•	互动量 = 转发 + 点赞 + 评论
A2. 峰值日贴文下钻
对互动量出现波峰的日期，自动下钻到具体引爆帖子：
JSON {   "peak_drilldown": [     {       "date": "2026-03-23",       "task": "MLBB",       "region": "global",       "top_posts": [         {           "author": "dimas.avt",           "author_region": "ID",           "post_topic": "Macel高光视频",           "post_url": "https://www.instagram.com/reels/xxx/",           "engagement": 75000         }       ]     }   ] } 

输出格式参考（给到客户的文本版）：
ML声量峰值分析：
	•	3/23
	•	dimas.avt（ID）发布 Macel高光视频，获得 75K 互动量。
	•	MLBB INDIA INS 发布 赛季段位MEME动画，获得 26K 互动量。

模块 B：社媒舆情（Sentiment Analysis）
B1. TOP5 贴文舆情概况（汇总卡片）
对周期内 SPD 相关 TOP5 帖子的评论进行整体汇总：
JSON {   "summary": {     "total_comments": 1200,     "sentiment_ratio": {       "positive": 25.0,       "neutral": 60.0,       "negative": 15.0     },     "key_opinions": [       {         "sentiment": "positive",         "region": "EN",         "opinion": "对 Naruto 联动皮肤表现出积极购买意愿",         "percentage": 4.1       },       {         "sentiment": "negative",         "region": "EN",         "opinion": "Julian × Itachi 角色适配质疑，技能机制与IP人设不符",         "percentage": 3.7       }     ]   } }

	•	按 正面 / 中性 / 负面 三档分组

	•	格式：{区域}：{一句话观点描述}（{百分比}%）
	•	示例：EN：玩家对 Naruto 联动中 Julian × Itachi 的角色适配提出质疑（3.7%）

四、处理管线（Pipeline Architecture）

各阶段详细说明
阶段
名称
处理逻辑
1
Crawl
按 TaskConfig 爬取 Facebook + Instagram 的帖子及其评论。需支持翻页、限速、反爬绕过。
2
Match
用布尔关键词表达式匹配帖子内容（文案 + hashtag），标记 matched_task（MLBB / SPD / both）。
3
Tag
按发帖账号归属打区域标签（EN / ID / TH / IN 等）。官方账号走账号映射表，UGC 走语言检测。同时标记 author_type。
4
Aggregate
按日期聚合互动量（likes + comments + shares），分 MLBB / SPD 两个任务维度 × 全球 / 泰国区域 两个视角，共 4 条时间序列。
5
Rank
仅对 SPD 相关帖子，按 engagement 降序排列，取 TOP5。同时识别波峰日期用于下钻。
6
Analyze
对 TOP5 帖子的全部评论执行：① 情感三分类（positive / neutral / negative）② 观点主题聚类（语义相近的评论归为同一观点）③ 提取代表性示例评论 + 翻译。
7
Render
按模板生成最终报告，包含：声量趋势图表 + 峰值下钻文本 + 舆情概况卡片 + TOP5 贴文详情表。

五、AI 处理要求
5.1 情感分析模型
参数
要求
分类标签
三分类：positive / neutral / negative
多语言支持
至少支持 EN、ID（印尼语）、TH（泰语）、PT（葡萄牙语）
Neutral 判定
纯提问、活动参与代码、无意义短评（emoji-only、tag friends）→ neutral
边界案例
反讽/戏谑需上下文判断，不能仅靠关键词
5.2 观点聚类逻辑
	•	对同一帖子下所有评论，先做情感分类
	•	同一情感类别内，按语义相似度聚类（如"皮肤像火影风格"的多种表述归为一个观点）
	•	每个观点计算占总评论数的百分比
	•	提取 2-3 条最具代表性的原文作为示例
	•	非英文评论需附带中文翻译
5.3 帖子主题摘要
	•	AI 生成一句话摘要（post_topic），描述帖子核心内容
	•	格式参考："Valir Ember Gaze 皮肤 PV" / "Macel 高光操作集锦" / "MPL 赛事战报"

六、注意事项
关键约束
	•	TOP5 帖子筛选范围：仅 SPD 相关帖子（brief 原文注明"仅SPD相关"）
	•	声量趋势范围：MLBB 和 SPD 都要出（用于对比联动活动占整体声量的比例）
	•	泰国区域单独拆分：声量趋势和峰值下钻都需要全球和泰国区域两个版本
	•	互动量定义：转发 + 点赞 + 评论（不含 views）
	•	图表需求：声量趋势部分原文有图表占位（block type 999），需输出可渲染的图表数据
